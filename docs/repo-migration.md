# 仓库迁移记录（2026-10-03）

这份文档说明**本仓库为什么以全新历史起步**，以及迁移过程中哪些东西保留了、哪些没有。
接手的人看到"提交数很少、没有历史贡献者"时，先读这里，别以为是数据丢了。

## 为什么迁移

本项目的代码源自 `DSH-APP/DSHA`（MIT），中间在仓库所有者自己的两个仓库上迭代过：

1. `zzy89216-gif/DSHA-zzy` —— 包名 `zzy.dsha.com`，发布 `v0.1.7-rc2-zzy.1` … `.8`
2. `zzy89216-gif/DSHA-zzy-kotlin` —— 过渡仓库，包名 `zzy.dsha.Kotlin`，发布 `.9` / `.10`

所有者希望最终仓库**不带此前仓库的贡献者记录**，因此两个仓库都已删除，并以全新历史重建于
本仓库（`zzy89216-gif/DSHA`）。

> 关键点：GitHub 的贡献者列表来自**提交的作者信息**。新建仓库后把旧历史推上去是没用的 ——
> 贡献者会原样跟过去。只有以全新历史（无父提交）起步才有效，本仓库就是这么做的。

### 迁移时改了什么

- 对外地址全部指向新仓库：`util/ProjectLinks.REPOSITORY`（应用内更新的唯一来源）、「关于」页、
  README 徽章、文档里的 Issues / Releases 链接。
- 发行版附件改名 `DSHA-<版本>.apk`（原 `DSHA-zzy-kotlin-<版本>.apk`）。
- `VERSION_CODE_BASE` 从 147 提到 1000：新仓库的 Actions 运行序号从 1 重新开始，
  沿用旧基数会算出比已发布版本更小的 versionCode，同一包名将无法覆盖安装。

### 两个只在迁移时才会踩到的坑

1. **首次发版必须显式填 tag。** 版本号是扫 `vX.Y.Z-…-zzy.N` 标签自增的，全新历史没有标签，
   留空会直接报错退出：`::error::没有可递增的历史标签，请填写 tag`。
   这一次填的是 `v0.2.0-zzy.1`；之后就能继续留空自增。
2. **CI 资产包要能自举。** 工作流优先读本仓库的 `runtime-assets` 发行版，没有时从
   `UPSTREAM_APK_URL` 下载一次并镜像过来。本仓库第一次构建就完成了这次镜像
   （日志里会写"资产来源"），之后不再外联。

## 如果以后需要旧历史

旧历史（14 个提交、12 个标签）在本机 `DSHA-zzy-kotlin.bundle` 里（不在本仓库）。用法：

```bash
git clone DSHA-zzy-kotlin.bundle old-history
cd old-history && git log --oneline | head
```

需要把它并入本仓库的话，建议只挑对当下有用的信息写进 CHANGELOG，**不要**把它合并进来 ——
那会把历史贡献者带回来，违背迁移目的。

## 已装旧版本的用户怎么办

`v0.1.7-rc2-zzy.9` / `.10` 的更新检查指向已删除的旧仓库，**取不到更新清单**。
受影响的用户手动安装一次 `v0.2.0-zzy.1` 即可恢复自动更新（同包名同签名，覆盖安装、数据保留）。
